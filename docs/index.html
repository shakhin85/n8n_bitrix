§ 02 Setup Guide
Chapter 02 · Guide

Настройка за шесть шагов

Следуй по порядку сверху вниз. Каждый занимает 2–5 минут.

ICreate a bot

Создай Telegram-бота

Открой Telegram, найди @BotFather и отправь команду /newbot. Придумай имя и username бота (должен заканчиваться на _bot). Получишь токен — скопируй и сохрани в менеджере паролей.

# BotFather диалог
Ты: /newbot
BotFather: Как назовём?
Ты: Tasks Bot
BotFather: Username?
Ты: my_tasks_bot
BotFather: Готово. Токен:
           1234567890:ABCdef...
Важно. Токен — это пароль. Не коммить в git, не шли в чаты.
IIRun engine

Запусти n8n

Самый простой способ — Docker Compose. В папке проекта выполни docker compose up -d. После запуска открой http://localhost:5678. Либо зарегистрируйся на n8n.cloud и пропусти этот шаг.

# Запуск через Docker Compose
docker compose up -d

# Логи
docker compose logs -f n8n

# Открой в браузере
http://localhost:5678
II½Public HTTPS

Получи публичный HTTPS

Telegram шлёт вебхуки только на HTTPS. n8n запущен локально в Docker — значит, нужен публичный адрес, который проксирует запросы на localhost:5678.

Рабочий способ для этого проекта — обратный SSH-туннель на внешний VPS. На сервере поднят HTTPS-терминатор (nginx/Caddy) на домене, который проксирует 127.0.0.1:5678 → локальный n8n через туннель.

Рекомендация. Для продакшена лучше сразу поднимать Docker-образ n8n на самом VPS: домен, Let's Encrypt через Caddy/Nginx, WEBHOOK_URL ведёт прямо на сервер. Так ты избавляешься от туннеля как класса — n8n доступен 24/7 без зависимости от локальной машины.
Важно. Если всё-таки держишь n8n локально — команду ssh -N -R нужно запускать каждый раз перед работой с ботом. Пока туннель не поднят, Telegram не сможет достучаться до n8n и триггер будет «висеть» в ожидании событий.
# Обратный SSH-туннель на VPS
# (оставь висеть в отдельном терминале)
ssh -N -R 5678:localhost:5678 root@<VPS_HOST>

# Флаги:
-N — не открывать shell, только форвард
-R — remote port forward (VPS → локалка)

# На VPS должен быть включён GatewayPorts
# в /etc/ssh/sshd_config, и HTTPS-прокси
# на домене из WEBHOOK_URL
# Альтернативы (если нет своего VPS)
cloudflared tunnel --url http://localhost:5678
ngrok http 5678
IIIBitrix webhook

Создай вебхук в Bitrix24

Перейди: Приложения → Разработчикам → Другое → Входящий вебхук. Выдай права на методы task и sonet_group. Скопируй сгенерированный URL — он нужен в следующем шаге.

# Формат URL вебхука
https://ВАШ_ДОМЕН.bitrix24.ru
  /rest/USER_ID/ТОКЕН/

# Необходимые scope-права:
✓ task — задачи
✓ sonet_group — рабочие группы
Внимание. Scope называется task в единственном числе, не tasks.
IVEnvironment

Заполни .env

Скопируй .env.example в .env и заполни переменные. Никогда не коммить реальный .env в git — он в .gitignore.

# n8n core
N8N_ENCRYPTION_KEY=случайная_строка_32_символа
N8N_BASIC_AUTH_USER=admin
N8N_BASIC_AUTH_PASSWORD=надёжный_пароль

# Public URL (для Telegram webhook)
WEBHOOK_URL=https://YOUR.duckdns.org

# Bitrix24 webhook из шага III
BITRIX24_WEBHOOK_URL=https://портал.bitrix24.ru/rest/ID/TOKEN/
VImport workflow

Импортируй воркфлоу

В n8n: Workflows → Import from file. Выбери файл bitrix-telegram-bot.json. Откроется граф автоматизации. Затем открой ноду Send Telegram Reply и выбери Telegram Credential с токеном из шага I.

# Telegram credentials в n8n
Settings → Credentials → Add Credential
→ Telegram API
→ Access Token: вставь_токен_из_шага_I
→ Save

# В ноде Send Telegram Reply
Credential for Telegram API:
  → Выбери созданный credential
VIPublish & test

Опубликуй и протестируй

Нажми кнопку Publish в правом верхнем углу воркфлоу — n8n активирует триггер Telegram. Теперь открой бота в Telegram и напиши первую команду.

# Первый тест в Telegram
/help — список всех команд

# Создать задачу
/backlog Моя первая задача

# Создать эпик в Скраме
/epic Переработка авторизации
Готово. Если бот ответил — задача появилась в Bitrix24.
Chapter 03 · Reference

Команды бота

Шесть команд покрывают весь цикл работы с задачами в Скраме Bitrix24.

/epic

Создать эпик

Добавляет эпик в Scrum-доску через метод tasks.api.scrum.epic.add. Эпик объединяет несколько задач спринта в одну крупную цель.

/epic Переработка авторизации
/sprint

Задача спринта

Создаёт задачу с дедлайном и приоритетом. Формат: до DD.MM и высокий / низкий.

/sprint API логина до 25.01 высокий
/backlog

Задача бэклога

Создаёт задачу без дедлайна — откладывается в бэклог для последующего планирования в спринте.

/backlog Улучшить фильтры отчётов
/task

Подзадача

Создаёт подзадачу, привязанную к родительской. Укажи ID через parent:#ID.

/task Написать тесты parent:#1234
/tasks

Мои задачи

Возвращает список активных незавершённых задач (до 10 штук) с ID и названием.

/tasks
/help

Справка

Показывает список всех команд и примеры прямо в Telegram. Хорошее начало для новичка.

/help
Chapter 04 · Security

Токены — не код.

Несколько правил, которые защитят тебя от утечки доступа к Bitrix24.

Публичный webhook с правами на задачи — это ключ к твоему порталу. Обращайся с ним как с паролем, а не как с кодом.

✕
Никогда

Не коммить workflows/ и .env в git

Файлы содержат URL вебхука с токеном. В публичном репозитории это открытый доступ к твоему порталу.

✓
Всегда

Добавь workflows/ и .env в .gitignore

Одна строчка в .gitignore гарантирует, что секреты никогда не попадут в репозиторий случайно.

✕
Никогда

Не передавай токены через мессенджеры

Telegram, Slack, email — не место для токенов. Используй менеджеры паролей: 1Password, Bitwarden, Vault.

✓
Всегда

Используй HTTPS для n8n

Telegram шлёт вебхуки только на HTTPS в продакшне. Для локалки — Cloudflare Tunnel или ngrok.

✕
Никогда

Не давай вебхуку лишние права

Выбирай только нужные scope: task и sonet_group. CRM, чаты, пользователи — это лишний доступ.

✓
Всегда

Ротируй токены периодически

Раз в несколько месяцев создавай новый вебхук и токен. Старые сразу деактивируй в Bitrix24 и BotFather.

§ 05 Questions
Chapter 05 · FAQ

Частые вопросы

Проверь по порядку: воркфлоу опубликован (кнопка Publish нажата); Telegram Credentials выбраны в ноде Send Telegram Reply; в n8n нет ошибок в разделе Executions. Чаще всего причина — незаполненные credentials или воркфлоу не опубликован.
GROUP_ID жёстко задан в нодах Prepare Sprint / Backlog / Subtask / Epic. Чтобы найти правильный ID — возьми свой webhook URL из шага III (тот же, что уже работает в воркфлоу) и добавь в конец sonet_group.get.json. Открой получившуюся ссылку в браузере — увидишь JSON со списком всех групп твоего портала. Найди нужную по полю NAME и скопируй её ID. Затем в n8n открой каждую из четырёх Prepare-нод и замени число в строке GROUP_ID: 314 на свой ID.
Да. Добавь бота в группу и выдай права на чтение сообщений (Admin → Read Messages). Команды из группового чата тоже обрабатываются через Telegram Trigger.
Нет. Воркфлоу полностью работает на n8n Community Edition — бесплатном self-hosted варианте. Для n8n.cloud достаточно бесплатного плана Starter.
Сейчас RESPONSIBLE_ID задан жёстко. Чтобы указывать исполнителя через команду, добавь синтаксис responsible:@username и в Parse Message сопоставляй username с ID через метод user.search.
В n8n кнопка называется Publish — она запускает триггер и делает воркфлоу готовым к приёму вебхуков. Это и есть активация. Без Publish Telegram Trigger не реагирует на входящие сообщения.
