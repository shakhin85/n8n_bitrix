# PRD: Telegram Bot для создания задач Bitrix24 через n8n

## 1. Overview

- **Problem**: Ручное создание задач в Bitrix24 (бэклог, спринт, эпики, задачи группы аналитики) требует множества кликов и переключений контекста
- **Goal**: Создание задач через Telegram-бота одной командой, используя n8n как оркестратор и Bitrix24 MCP для API
- **Target users**: Руководитель группы аналитики, использующий Scrum-методологию в Bitrix24

## 2. Requirements

### Functional Requirements

- **FR-1**: Telegram-бот принимает команды для создания задач разных типов (Эпик, Спринт, Бэклог, Задача)
- **FR-2**: n8n workflow обрабатывает сообщение, парсит поля и создаёт задачу через Bitrix24 MCP
- **FR-3**: Поддержка полей: название, описание, приоритет, дедлайн, ответственный, родительская задача (для подзадач)
- **FR-4**: Бот подтверждает создание задачи, возвращает ID и ссылку
- **FR-5**: Возможность просмотра списка задач (моя группа аналитики)
- **FR-6**: Команда `/help` — справка по доступным командам

### Non-Functional Requirements

- **NFR-1**: Время отклика бота < 5 секунд
- **NFR-2**: Обработка ошибок API Bitrix24 с понятными сообщениями пользователю
- **NFR-3**: Все секреты (токены, webhook URL) хранятся в `.env`
- **NFR-4**: n8n работает в Docker, данные персистентны (volume)

## 3. User Stories

- **US-1**: Как руководитель, я пишу `/epic Разработать модуль отчётов` → бот создаёт эпик в Bitrix24
- **US-2**: Как руководитель, я пишу `/sprint "Настроить API" до 20.01 высокий` → бот создаёт задачу спринта с дедлайном и приоритетом
- **US-3**: Как руководитель, я пишу `/backlog Добавить фильтрацию по датам для дашборда продаж` → бот создаёт задачу бэклога
- **US-4**: Как руководитель, я пишу `/tasks` → бот показывает мои активные задачи
- **US-5**: Как руководитель, я пишу `/help` → бот показывает все доступные команды

## 4. Technical Scope

- **Tech stack**:
  - n8n (Docker)
  - Telegram Bot API
  - Bitrix24 MCP Server (через apidocs.bitrix24.ru/sdk/mcp.html)
  - MCP Forgetful (для сохранения контекста/прогресса)

- **Dependencies**:
  - Docker (установлен)
  - Telegram Bot Token (от @BotFather)
  - Bitrix24 Webhook URL (из MCP конфига)
  - MCP сервер Bitrix24 (подключён к n8n или Qwen Code)

- **Integration points**:
  - Telegram → n8n (Webhook)
  - n8n → Bitrix24 MCP (REST API через MCP)
  - Bitrix24 MCP → Bitrix24 Cloud/Self-hosted

- **Data model (Bitrix24 Tasks)**:
  - `task.title` — название
  - `task.description` — описание
  - `task.priority` — приоритет (0=Низкий, 1=Средний, 2=Высокий)
  - `task.deadline` — дедлайн (ISO 8601)
  - `task.responsibleId` — ответственный (user ID)
  - `task.parentId` — родитель (для подзадач)
  - `task.groupId` — группа аналитики
  - `task.tags` — теги (epic, sprint, backlog)

## 5. CLI / Bot Interface

### Команды Telegram-бота

| Команда | Описание | Пример |
|---------|----------|--------|
| `/epic <название> [описание]` | Создать эпик | `/epic Модуль отчётов Добавить аналитику по продажам` |
| `/sprint <название> [дедлайн] [приоритет]` | Создать задачу спринта | `/sprint API логина до 20.01 высокий` |
| `/backlog <название> [описание]` | Создать задачу бэклога | `/backlog Кэширование запросов Redis` |
| `/task <название> [parent:#ID] [приоритет]` | Создать подзадачу | `/task Реализовать endpoint parent:#123 высокий` |
| `/tasks` | Показать активные задачи | `/tasks` |
| `/help` | Справка | `/help` |

### Парсинг сообщений

- `до DD.MM` — дедлайн
- `высокий/средний/низкий` — приоритет
- `parent:#ID` или `#ID` — родительская задача
- Всё после команды — название + описание

## 6. Architecture

```
┌─────────────┐     Webhook      ┌──────────────────────────────────────────────┐
│  Telegram   │ ───────────────► │  n8n (Docker)                                │
│   Bot       │ ◄────────────── │  ┌─────────┐  ┌──────────┐  ┌─────────────┐ │
│             │    Response      │  │Telegram  │→ │  Parse   │→ │ Bitrix24    │ │
│  Пользов-ль │                  │  │ Trigger │  │  Message │  │ MCP Node    │ │
└─────────────┘                  │  └─────────┘  └──────────┘  └─────────────┘ │
                                 └──────────────────────────────────────────────┘
                                              │
                                              ▼
                                       Bitrix24 Cloud
                                       (через MCP)
```

### n8n Workflow Nodes

1. **Telegram Trigger** — receives message
2. **Switch/Router** — routes by command (/epic, /sprint, /backlog, /task, /tasks, /help)
3. **Code Node** — parses message (title, description, deadline, priority, parent)
4. **HTTP Request / MCP** — calls Bitrix24 API
5. **Telegram Reply** — sends confirmation

## 7. Acceptance Criteria

- [ ] Бот создаёт эпик по команде `/epic` и возвращает ID + ссылку
- [ ] Бот создаёт задачу спринта с дедлайном и приоритетом
- [ ] Бот создаёт задачу бэклога
- [ ] Бот создаёт подзадачу с привязкой к родителю
- [ ] Команда `/tasks` возвращает список активных задач
- [ ] Команда `/help` показывает справку
- [ ] Ошибки API обрабатываются с понятными сообщениями
- [ ] Все секреты в `.env`, не в коде
- [ ] n8n работает в Docker, данные сохраняются при перезапуске

## 8. Out of Scope

- Редактирование существующих задач (только создание)
- Удаление задач
- Назначение ответственных (по умолчанию — создатель)
- Файлы/вложения к задачам
- Комментарии к задачам

## 9. Open Questions

- **Q1**: Какой Bitrix24 MCP сервер используется? Нужен ли отдельный webhook URL?
- **Q2**: Нужно ли создавать задачи от имени пользователя или от имени бота?
- **Q3**: Какие статусы задач ставить по умолчанию (Новая, В работе)?
- **Q4**: Нужна ли валидация дедлайнов (нельзя поставить прошедшую дату)?
- **Q5**: Нужно ли уведомлять ответственного при создании задачи?
